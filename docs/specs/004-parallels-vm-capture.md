# Spec 004: Parallels VM Screen Capture

| | |
|---|---|
| Status | Implemented |
| Audience | Implementing agents / engineers |
| Scope | `parallels_vm_capture` tool; `Capture` on the Parallels service (temp file → memory → cleanup); `internal/imaging` PNG downscaler; MCP image content result; tests; QA doc |
| Out of scope | Capturing a sub-area/region, video/recording, OCR, JPEG/WebP output, `prlctl exec`-based or guest-agent screenshots, persisting screenshots — follow-up specs |

## 1. Goal

Let an AI client **see a VM's screen**. The tool runs `prlctl capture <vm> --file <path>`, reads the resulting PNG into memory, deletes the file, optionally downscales it, and returns it as a native MCP **image content block** (plus a short text block with metadata).

```
prlctl capture <vm_id | vm_name> --file <name>
```

`prlctl` only writes to a file, so the service owns a private temp directory per call, hands prlctl a path inside it, reads the bytes, and removes the directory before returning, on every path (success, error, timeout, cancel).

### Acceptance criteria

1. `make check` and `make test-e2e` pass; no capture is ever executed in CI.
2. `parallels_vm_capture` is listed in both fleet and VM mode whenever the module is enabled, and is absent when `prlctl`/`prlsrvctl` are missing.
3. A call returns `content[0]` = text (VM, dimensions, bytes) and `content[1]` = `image` block with `mimeType: "image/png"` and valid base64 PNG data; the structured output carries metadata only (never the image).
4. After every call, success or failure, no `pdfm-mcp-capture-*` directory remains in the OS temp dir.
5. Default output is downscaled so the long edge is ≤ 1568 px; `full_resolution: true` returns prlctl's PNG byte-for-byte.
6. On the real machine (Parallels 27, running VM) the Inspector renders the screenshot, and Claude can describe what is on the VM screen.
7. Every step in `docs/qa/004-parallels-vm-capture-QA.md` passes.

## 2. Decisions

| Topic | Decision | Rationale |
|---|---|---|
| Result format | MCP `ImageContent` (`type: "image"`, base64, `mimeType: image/png`) + `TextContent` metadata. **Not** base64 inside text or structured output | Clients forward `image` blocks to the model as vision input; base64 in text is treated as tokens of gibberish. The Go SDK takes raw `[]byte` and base64-encodes on the wire |
| Temp handling | `os.MkdirTemp("", "pdfm-mcp-capture-*")` (mode 0700), file `capture.png` inside it, `defer os.RemoveAll(dir)` | Unique per call (safe under concurrency), unguessable, private to the user, path is generated by us and never derived from tool input. A directory (not a temp file) avoids prlctl failing on an existing empty file and cleans up any side files |
| Layering | Service `Capture` returns **raw PNG bytes**. Resizing lives in a pure `internal/imaging` package. The tool orchestrates both | Keeps the service about prlctl only, and makes image logic unit-testable with synthetic images |
| Downscale | Default long edge ≤ **1568 px**, aspect preserved, **never upscale**. Arg `max_dimension` (256 to 4096) overrides, `full_resolution: true` skips resizing | Vision models downscale large images anyway; a Retina VM capture is wasted payload and latency. Text stays legible at 1568 |
| Resampler | `golang.org/x/image/draw` `CatmullRom` | Stdlib has no scaler, and nearest/box filters smear UI text. **New direct dependency**, justified here per AGENTS.md. Fallback if rejected: a ~40-line area-average resampler in `internal/imaging` |
| Output encoding | PNG (re-encoded after resize, passthrough when not resized) | Lossless, best for UI text. JPEG/WebP is a follow-up |
| Target resolution | Reuse `resolvePowerTarget` (spec 003): VM mode uses the configured target and rejects explicit `vm_id`; fleet mode requires `vm_id` (id or name). Validated with `ValidateVMRef`, passed as one argv element | One mode contract for every VM-scoped tool |
| Timeout | 30 s (`captureTimeout`), applied as an explicit context deadline | A screenshot should be near-instant; do not inherit the 180 s power cap |
| Cache | Capture does **not** touch the VM list cache | It does not change VM state |
| Annotations | `ReadOnlyHint: true`, `OpenWorldHint: false` | No VM mutation; nothing leaves the machine except via the client |
| Logging | Log VM ref, dimensions, byte counts, duration. **Never log image bytes** | Screenshots can contain secrets; see section 7 |

### 4.2 `internal/parallels/service/capture.go`

```go
package service

import (
	"bytes"
	"context"
	"errors"
	"fmt"
	"io"
	"os"
	"path/filepath"
	"time"

	"github.com/cjlapao/pdfm-mcp/internal/parallels/interfaces"
)

const (
	// captureTimeout bounds one screenshot; it should take well under a second.
	captureTimeout = 30 * time.Second
	// maxCaptureBytes bounds the PNG we are willing to load into memory.
	maxCaptureBytes = 32 << 20 // 32 MB
)

var pngMagic = []byte{0x89, 'P', 'N', 'G', '\r', '\n', 0x1a, '\n'}

func (s *service) Capture(ctx context.Context, vmRef string) (interfaces.CaptureResult, error) {
	if !s.enabled {
		return interfaces.CaptureResult{}, ErrNotEnabled
	}
	ref, err := ValidateVMRef(vmRef)
	if err != nil {
		return interfaces.CaptureResult{}, err
	}

	dir, err := os.MkdirTemp("", "pdfm-mcp-capture-")
	if err != nil {
		return interfaces.CaptureResult{}, fmt.Errorf("create capture temp dir: %w", err)
	}
	defer func() {
		if rerr := os.RemoveAll(dir); rerr != nil {
			s.logger.Warn("could not remove capture temp dir", "dir", dir, "err", rerr)
		}
	}()
	file := filepath.Join(dir, "capture.png")

	runCtx, cancel := context.WithTimeout(ctx, captureTimeout)
	defer cancel()

	start := time.Now()
	// argv: capture <vm> --file <generated path>. No shell, single elements.
	if _, err := s.runner.Run(runCtx, s.prlctlPath, "capture", ref, "--file", file); err != nil {
		s.logger.Warn("prlctl capture failed", "vm", ref, "err", err)
		return interfaces.CaptureResult{}, err
	}

	png, err := readCapture(file)
	if err != nil {
		return interfaces.CaptureResult{}, err
	}
	s.logger.Info("prlctl capture completed", "vm", ref, "bytes", len(png), "took", time.Since(start))
	return interfaces.CaptureResult{PNG: png, CapturedAt: time.Now().UTC()}, nil
}

// readCapture loads the file prlctl wrote, with size and format checks.
func readCapture(path string) ([]byte, error) {
	f, err := os.Open(path) // #nosec G304 -- path is generated by Capture inside its own private temp dir
	if err != nil {
		if errors.Is(err, os.ErrNotExist) {
			return nil, errors.New("prlctl capture reported success but produced no file (is the VM running?)")
		}
		return nil, fmt.Errorf("open capture: %w", err)
	}
	defer f.Close()

	// Read at most max+1 bytes so an oversized file is detected without loading it all.
	data, err := io.ReadAll(io.LimitReader(f, maxCaptureBytes+1))
	if err != nil {
		return nil, fmt.Errorf("read capture: %w", err)
	}
	if len(data) > maxCaptureBytes {
		return nil, fmt.Errorf("capture is larger than %d bytes", maxCaptureBytes)
	}
	if len(data) == 0 {
		return nil, errors.New("capture file is empty")
	}
	if !bytes.HasPrefix(data, pngMagic) {
		return nil, errors.New("capture file is not a PNG")
	}
	return data, nil
}
```

Notes:

- **Cleanup is unconditional** via `defer`, including when `Run` fails, the context expires, or the file is invalid. The real runner kills the child on context expiry (spec 002), and the directory is removed after `Run` returns.
- The runner's stdout is ignored (prlctl prints nothing useful), and is never inherited (stdout rule).
- No pre-check of VM state: prlctl is the authority (stopped VM, unknown VM and similar surface as tool errors with its stderr).

## 5. Imaging (`internal/imaging`)

Pure functions, no knowledge of Parallels or MCP.

```go
package imaging

// Limits.
const (
	DefaultMaxDimension = 1568
	MinMaxDimension     = 256
	MaxMaxDimension     = 4096
	maxPixels           = 100_000_000 // decompression-bomb guard on the INPUT
)

// Result describes the (possibly resized) image.
type Result struct {
	Data                      []byte // PNG bytes
	Width, Height             int
	OriginalWidth, OriginalHeight int
	Resized                   bool
}

// Downscale returns src unchanged (same bytes, Resized=false) when its long
// edge is already <= maxDim. Otherwise it decodes, scales to fit maxDim on
// the long edge preserving aspect ratio with CatmullRom, and re-encodes PNG.
// It never upscales.
func Downscale(src []byte, maxDim int) (Result, error)

// Dimensions reads the size from the PNG header without decoding pixels.
func Dimensions(src []byte) (w, h int, err error)
```

Rules:

1. Call `png.DecodeConfig` first. Reject input with `w*h > maxPixels` **before** the full decode.
2. When no resize is needed, return the original bytes untouched (this is also the `full_resolution` path: the tool simply skips `Downscale` and calls `Dimensions`).
3. Resize target: `scale = maxDim / max(w, h)`; `newW = max(1, round(w*scale))`, same for height. Convert the source to `*image.NRGBA`/`RGBA` as needed before `draw.CatmullRom.Scale`.
4. Encode with `png.Encoder{CompressionLevel: png.DefaultCompression}`. No metadata is added.
5. Validate `maxDim` at the tool layer (256 to 4096); `Downscale` also returns an error for out-of-range values.

## 6. Tool layer

### 6.1 `internal/tools/parallels_vm_capture.go`

```go
// CaptureInput is the argument schema of parallels_vm_capture.
type CaptureInput struct {
	VMID           string `json:"vm_id,omitempty" jsonschema:"VM id or name to capture"`
	MaxDimension   int    `json:"max_dimension,omitempty" jsonschema:"longest edge in pixels the image is downscaled to (256-4096, default 1568)"`
	FullResolution bool   `json:"full_resolution,omitempty" jsonschema:"return the screenshot at native resolution without downscaling"`
}

// CaptureOutput is the structured metadata. The image itself is delivered
// as an image content block, never in structured output.
type CaptureOutput struct {
	VMID           string `json:"vm_id" jsonschema:"the VM id or name that was captured"`
	MIMEType       string `json:"mime_type" jsonschema:"image MIME type"`
	Width          int    `json:"width" jsonschema:"returned image width in pixels"`
	Height         int    `json:"height" jsonschema:"returned image height in pixels"`
	OriginalWidth  int    `json:"original_width" jsonschema:"native screen width in pixels"`
	OriginalHeight int    `json:"original_height" jsonschema:"native screen height in pixels"`
	Resized        bool   `json:"resized" jsonschema:"true when the image was downscaled"`
	Bytes          int    `json:"bytes" jsonschema:"size of the returned image in bytes"`
	CapturedAt     string `json:"captured_at" jsonschema:"RFC3339 UTC capture time"`
}
```

Handler flow (`VMCapture(ctx, req, in)`):

1. `svc := parallels.GetInstance()`; `target, err := resolvePowerTarget(svc, in.VMID)`.
2. Validate `max_dimension`: `0` means default; otherwise must be in 256..4096 → tool error otherwise.
3. `res, err := svc.Capture(ctx, target)`.
4. If `full_resolution`: `w, h := imaging.Dimensions(res.PNG)`, output bytes = `res.PNG`. Else `imaging.Downscale(res.PNG, maxDim)`.
5. Enforce `maxResultBytes = 10 << 20` on the final PNG; on overflow return a tool error advising a smaller `max_dimension` (guards stdio line size and client limits).
6. Return:

```go
return &mcp.CallToolResult{
	Content: []mcp.Content{
		&mcp.TextContent{Text: fmt.Sprintf(
			"Screenshot of VM %s: %dx%d px (native %dx%d), %d bytes, PNG.",
			target, out.Width, out.Height, out.OriginalWidth, out.OriginalHeight, out.Bytes)},
		&mcp.ImageContent{Data: data, MIMEType: "image/png"}, // SDK base64-encodes on the wire
	},
}, out, nil
```

The text block goes **first**: it gives the model context and is the fallback for clients that cannot render images.

> **Verify against the installed SDK:** when the handler returns a non-nil `*mcp.CallToolResult` with `Content` set *and* a typed output, the SDK must keep the supplied `Content` and attach `out` as `StructuredContent` (it should only auto-generate content when `Content` is nil). Cover this with the protocol test below. If the SDK overwrites `Content`, return `CaptureOutput` as `any` with no output schema and drop structured output, and record it under Deviations.

## 7. Security and privacy

- **No input-derived paths.** The only path passed to prlctl is `<MkdirTemp dir>/capture.png`, generated by us. Tool arguments never reach the filesystem layer.
- **Private temp dir (0700), removed unconditionally.** The screenshot never persists on disk past the call. Do not add a "keep file" option.
- **No shell.** argv elements only; `vm_id` goes through `ValidateVMRef`.
- **Bounded memory.** 32 MB read cap, 100 MP decode cap, 10 MB result cap.
- **Never log pixel data** or base64. Logs carry VM ref, sizes and timings only.
- **Screenshots are sensitive data.** The image is returned to the MCP client and therefore reaches whichever model provider the client uses. A VM screen can show credentials, tokens, customer data or confidential source. README must state this. For Parallels-internal use, remind users not to capture VMs showing such material while connected to an external AI service.

## 8. Edge cases and invariants

| Case | Behaviour |
|---|---|
| VM stopped, suspended or paused | prlctl fails → tool error with its stderr (no pre-check) |
| Unknown VM | prlctl stderr surfaced as a tool error |
| prlctl exits 0 but no file | error: "produced no file (is the VM running?)" |
| File empty or not PNG | error, directory still removed |
| File > 32 MB | error, directory still removed |
| Context cancelled or 30 s timeout | runner kills child, error returned, directory removed |
| Very large native resolution (for example 5K) | decoded under the 100 MP cap, then downscaled |
| Native smaller than `max_dimension` | returned byte-for-byte, `resized: false` |
| Concurrent captures | independent temp dirs; no shared state |
| Fleet mode without `vm_id` / VM mode with `vm_id` | same errors as spec 003 |
| Module disabled | tool not registered |
| stdout | untouched: runner buffers, nothing prints |

## 9. Testing

1. **`internal/imaging/imaging_test.go`**: build synthetic PNGs with `image/png`. Cases: 3000×2000 → 1568×1045 (aspect preserved within 1 px); portrait; already-small input returns identical bytes; `maxDim` out of range → error; non-PNG → error; oversize pixel count rejected without full decode (craft a header-only PNG with huge IHDR dimensions); output decodes as valid PNG.
2. **`service/capture_test.go`**: a fake runner that parses `--file` from argv and writes a synthetic PNG to it. Assert: exact argv `[capture <vm> --file <path>]` with `<path>` inside a `pdfm-mcp-capture-*` dir; returned bytes equal the written bytes; **directory removed** after success; after runner error; after "no file written"; after non-PNG; after empty file; after oversize (fake writes 33 MB); after context cancel (fake blocks on `ctx.Done()`); invalid `vmRef` (empty/NUL/over-long) rejected before any exec; module disabled → `ErrNotEnabled`; capture does not invalidate the VM cache (a following `ListVMs` is still `Refreshed == false`).
3. **`tools/parallels_capture_test.go`**:
   - Table-driven handler tests over both modes: VM mode uses the configured target; VM mode + explicit `vm_id` rejected; fleet without `vm_id` rejected; fleet with `vm_id` targets it.
   - `max_dimension` validation (255 and 4097 rejected; 0 → default; 512 honoured); `full_resolution` returns the original bytes and dimensions.
   - Result-size cap triggers a tool error.
   - **In-memory protocol test**: `tools/list` shows `parallels_vm_capture` in both modes, with `vm_id` in `required` only in fleet mode and no `["null","array"]` unions; `tools/call` returns `Content[0]` as `*mcp.TextContent` and `Content[1]` as `*mcp.ImageContent` with `MIMEType == "image/png"`, `Data` decoding as a PNG of the expected (downscaled) size; `StructuredContent` carries metadata and **does not** contain the image data.
4. **`test/e2e/stdio_test.go`**: extend the gating test (skips without `prlctl`) to assert `parallels_vm_capture` is **listed** in fleet mode. Executing a real capture is opt-in only: run it when `PDFM_MCP_E2E_CAPTURE_VM` is set to a running VM id, and assert an image block with decodable PNG data. Never default-on.
5. **`docs/qa/004-parallels-vm-capture-QA.md`**: manual steps on a real machine: running VM capture default and `full_resolution`; `max_dimension: 512`; stopped VM error; unknown VM error; fleet and VM mode contract; temp dir check (`ls "$TMPDIR" | grep pdfm-mcp-capture` is empty after calls, including a failed one); Inspector renders the image; Claude describes the screen.

## 12. Known unknowns / verification notes

- **Synchronous write.** Assumed that when `prlctl capture` exits 0 the file is fully written. If QA shows truncated or missing files, add a short bounded poll (for example up to 2 s, 50 ms steps) for a stable non-zero size before reading.
- **VM state requirements.** Assumed the VM must be running (and possibly needs a display). Behaviour for paused or suspended VMs is surfaced as prlctl's error; confirm in QA and document the exact messages.
- **Multiple displays.** The Parallels docs describe a single `--file` target; what is captured for multi-monitor guests is unverified.
- **Client image limits.** Individual clients may cap image size or count per result. The 1568 px default and the 10 MB result cap are conservative; tune after testing with Claude Desktop and Claude Code.
- **SDK result handling** for non-nil `CallToolResult` + typed output (see 6.1) is verified against the installed go-sdk v1.8.0: the supplied `Content` is kept and the typed output is attached as `StructuredContent`. No fallback needed (covered by the in-memory protocol test).
- The prlctl help text and an actual run on the installed version (`prlctl capture --help`) are the source of truth for flags if they differ from the documentation quoted in this spec.

### Deviations (fill in during implementation)

- `readCapture` closes the file explicitly (`f.Close()` with the error
  propagated when the read succeeded) instead of `defer f.Close()`: the repo
  lint (errcheck) rejects unchecked `Close` returns. Read-then-close
  semantics are unchanged.
- The e2e opt-in real capture runs against the **fleet** session
  (`PDFM_MCP_E2E_CAPTURE_VM` + explicit `vm_id`), which matches the section 9
  contract; VM mode would correctly reject the explicit `vm_id`.
- Otherwise as specified. The section 6.1 SDK verification resolved
  in favour of the main path (no fallback needed).
