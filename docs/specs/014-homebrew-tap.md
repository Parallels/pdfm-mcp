# Spec 014: Homebrew Tap Distribution

| | |
|---|---|
| Status | Implemented (local verification complete 2026-10-09; tap repo created 2026-10-12; first stable cask publish pending release owner) |
| Audience | Implementing agents / engineers, release owner |
| Scope | A dedicated tap repository, the GoReleaser `homebrew_casks` block, token/permissions, tap CI, install/upgrade/uninstall docs, MCP client configuration notes |
| Depends on | Spec 013 (signed, notarized universal macOS archive on a GitHub Release) |
| Out of scope | Submitting to `homebrew/homebrew-cask` or `homebrew/homebrew-core` (public, review by Homebrew maintainers), Linux/Linuxbrew |

## 1. Goal

A Mac developer at Parallels can run:

```sh
brew tap <org>/tap            # once (name per section 2)
brew install --cask <org>/tap/pdfm-mcp
brew upgrade --cask pdfm-mcp  # later
```

and get `pdfm-mcp` on PATH, with every release published to the tap **automatically** by the release workflow.

### Acceptance criteria

1. Tagging a stable release (spec 013) commits an updated `Casks/pdfm-mcp.rb` to the tap repo with the new version, URL and sha256, with no manual step.
2. On a clean Mac, `brew install --cask <tap>/pdfm-mcp` installs without any Gatekeeper prompt and `pdfm-mcp --version` prints the released version.
3. `brew upgrade --cask`, `brew uninstall --cask`, and `brew reinstall --cask` work; uninstall removes the symlink.
4. Pre-release tags do **not** update the tap.
5. The tap repo CI (`brew style`, `brew audit --cask`) passes on every change.
6. No token or secret is present in the tap repo or in the generated cask.
7. `docs/qa/014-homebrew-tap-QA.md` passes.

## 2. Decisions

| Topic | Decision | Rationale |
|---|---|---|
| Form | **Cask** with a `binary` stanza, produced by GoReleaser `homebrew_casks` | GoReleaser's `brews` (formula) publisher is deprecated for pre-built binaries; casks are the supported route for prebuilt artifacts |
| Alternative considered | A **formula that builds from source** (`depends_on "go" => :build`) | Avoids notarization and Gatekeeper entirely (brew builds locally) but needs source access (private repo), a Go toolchain on every machine, and is slower. Keep as the **fallback** if notarization is not available |
| Tap location | `<org>/homebrew-tap` (e.g. `Parallels/homebrew-tap`), separate from the product repo. Brew requires the `homebrew-` prefix | Standard; keeps release commits out of the product repo history |
| Visibility | Follows the publication gate in spec 013 (section 3). Private tap + private release assets is possible but needs authenticated downloads (section 6) | Source and binaries are confidential by default |
| Auth to push to the tap | Fine-grained PAT (`HOMEBREW_TAP_TOKEN`) with `contents:write` on the tap repo only, stored as a secret in the `release` environment; or a GitHub App token if the org prefers | Least privilege; the default `GITHUB_TOKEN` cannot push to another repo |
| Signing | The binary is already notarized (013), so **no quarantine-stripping hook** is generated | Quarantine hooks are a workaround for unsigned binaries; Homebrew is also deprecating the Ruby `postflight` they rely on |
| Binary name on PATH | `pdfm-mcp` (from the archive root) | Matches MCP client configs |
| Arch handling | Single universal archive, one `url`, no `on_arm`/`on_intel` blocks | Spec 013 produces one macOS artifact |
| Update policy | Stable tags only (`skip_upload: auto`) | Pre-releases must not reach users |

The tap contains **no source code** and no secrets.

## 4. GoReleaser configuration (added to `.goreleaser.yaml` from spec 013)

```yaml
homebrew_casks:
  - name: pdfm-mcp
    ids: [default]                 # the archive id from spec 013
    directory: Casks
    homepage: "https://github.com/Parallels/pdfm-mcp"   # confirm; internal docs URL is fine
    description: "MCP server for controlling Parallels Desktop VMs (list, power, capture, exec, keyboard, sequences)"
    license: "<SPDX id or 'Proprietary' as decided by Legal>"
    binaries: [pdfm-mcp]
    skip_upload: auto              # skip for pre-release tags
    repository:
      owner: Parallels        # confirm
      name: homebrew-tap           # confirm
      branch: main
      token: "{{ .Env.HOMEBREW_TAP_TOKEN }}"
    commit_author:
      name: pdfm-mcp release bot
      email: <bot-email>           # an org-owned address, not a personal one
    commit_msg_template: "pdfm-mcp {{ .Tag }}"
    caveats: |
      GUI MCP clients (Claude Desktop) do not use your shell PATH.
      Use the absolute path in their config:
        #{HOMEBREW_PREFIX}/bin/pdfm-mcp
```

Implementation notes:

- The exact key names (`binaries`, `skip_upload`, `repository`, `commit_author`, `caveats`, `ids`) must be checked against the installed GoReleaser's `homebrew_casks` reference; this block is the intended shape, not a verified one.
- Because the binary is notarized there must be **no** `hooks.post.install` quarantine hook. If a hook ever becomes necessary (an unsigned build), use the declarative form GoReleaser is adding (`install_steps`, tracked for v2.19) rather than the deprecated Ruby `postflight`, and record it as a deviation.
- The generated `Casks/pdfm-mcp.rb` must contain `version`, `sha256`, `url` (the release asset), `name`, `desc`, `homepage`, `binary "pdfm-mcp"`, and no credentials.

### Expected cask shape (illustrative)

```ruby
cask "pdfm-mcp" do
  version "0.1.0"
  sha256 "<sha256 of the archive>"

  url "https://github.com/Parallels/pdfm-mcp/releases/download/v#{version}/pdfm-mcp_#{version}_darwin_universal.tar.gz"
  name "pdfm-mcp"
  desc "MCP server for controlling Parallels Desktop VMs"
  homepage "https://github.com/Parallels/pdfm-mcp"

  binary "pdfm-mcp"
end
```

## 5. Tap CI (`.github/workflows/ci.yml` in the tap repo)

On PR and push: run on `macos-latest`: `brew style --cask Casks/pdfm-mcp.rb` and `brew audit --cask --strict --online <tap>/pdfm-mcp` (the online audit is skipped for a private tap that cannot be reached anonymously; record that). A scheduled weekly run catches Homebrew rule changes before a release hits them.

## 6. Private repository mode

If the product repo (and therefore the release asset URLs) is private, an anonymous `curl` of the asset returns 404, so a plain cask will fail for users. Options, in order of preference:

1. **Make the release assets publicly downloadable** from a separate public location approved by Parallels (for example a public releases-only repo or an internal artifact store reachable on the corporate network/VPN). Point `url` at it.
2. Keep assets private and use an authenticated download strategy in the cask (`url ..., header: "Authorization: token #{ENV["HOMEBREW_GITHUB_API_TOKEN"]}"`-style or a custom `DownloadStrategy`), requiring each developer to export a token. Higher friction and token-handling risk; document the token scope (read-only, `contents:read`) and never ask users to paste tokens into chat or tickets.
3. Fallback formula that builds from source (section 2).

The chosen option must be recorded in Deviations and in `docs/release.md`. Do not store any token in the tap, the cask, or the README.

(`/usr/local/bin/pdfm-mcp` on Intel Macs.) Optional single-VM mode: add `"args": ["--vm-id", "<vm id or name>"]`. Upgrade: `brew upgrade --cask pdfm-mcp`. Uninstall: `brew uninstall --cask pdfm-mcp`, then remove the MCP client entry.

## 8. Security

- The tap token has the narrowest scope possible and lives only in the `release` environment secrets (spec 013 section 7).
- The cask pins the archive by sha256; the release must never be re-uploaded under the same tag.
- No `post_install`/`postflight` scripts, no network calls at install time, no `sudo`.
- The cask must not auto-register the server with any MCP client (the user opts in by editing their client config).
- Treat tap commits as release artifacts: branch protection on `main`, required review for non-bot changes.

## 9. Testing

1. **Dry run**: `goreleaser release --snapshot --clean --skip=publish,notarize` generates the cask locally in `dist/`; inspect it against the expected shape.
2. **Tap CI** green on the generated cask (copy it into a scratch tap).
3. **Clean Mac / fresh user**: install, version check, launch from a GUI client with the absolute path, upgrade from the previous release, uninstall.
4. **Pre-release**: push `vX.Y.Z-rc.1` and confirm the tap is untouched.
5. **Negative**: remove `HOMEBREW_TAP_TOKEN` and confirm the release workflow fails loudly at the tap step *after* the GitHub Release is already created (the release itself must not be lost); document the manual re-run procedure.
6. `docs/qa/014-homebrew-tap-QA.md` with the steps above.

### Deviations (fill in during implementation)

- The cask is published only when repository variable `PUBLISH_HOMEBREW` is `'true'` **and** the tag is stable, via the `tap` job's `if` in `release.yml`, so internal releases do not fail at the tap step before a tap exists.
- Tap owner/name and bot email are `<...>` placeholders in `release.yml` until confirmed.
- **Verified 2026-10-09** against GoReleaser 2.12.5 + Homebrew 4.x: the binary-cask key is `binary` (singular), not `binaries`; the generated cask carries `version`/`sha256`/`url`/`name`/`desc`/`homepage`/`binary`/`caveats` and no token or quarantine hook.
- **Design change (spec 014 section 4 / acceptance 5):** GoReleaser only *generates* the cask (`skip_upload: true`; `repository` is still required for the pipe to run but is unused). A dedicated `tap` job in `release.yml` clones the tap repo, runs `brew style --fix` then `brew style` (must be clean) and `brew audit --cask --strict`, then commits and pushes. Rationale: GoReleaser's cask template emits stanza order that `brew style` rejects, and the tap's own CI (acceptance 5) must stay green — normalizing inside the pipe is not possible.
- **Caveats are a single line**: GoReleaser emits each caveat line as a bare string literal inside `caveats do … end`, and Homebrew uses only the block's last expression — multi-line caveats silently drop every line but the last (confirmed with `brew style`, which flags the dropped lines as void literals and deletes them under `--fix`).
- `desc` shortened to <80 characters (Homebrew's limit; the draft's 98-char description failed `brew style`/`audit`).
- Homebrew strips the `homebrew-` prefix from tap *names*: the repo is `Parallels/homebrew-tap` but the tap is `Parallels/tap` (verified locally). A freshly cloned tap needs `brew trust <owner>/tap` before audit (Homebrew 4.x untrusted-tap guard; non-interactive).
- The `license` stanza is omitted from the generated cask while `license` holds the Legal placeholder: GoReleaser renders it only for a known SPDX id.
